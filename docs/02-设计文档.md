# TodayNote 博客系统设计文档

## 1. 设计目标
本文档用于承接需求文档，明确系统页面结构、模块划分、核心数据模型、接口设计与交互规则，确保产品需求可拆分、可开发、可测试。

本轮设计统一采用“文章 Article”术语，不再混用 `Post` 与 `Article`。接口基础路径统一为 `/api/articles`、`/api/users`、`/api/tags` 等形式，与后端现有工程命名保持一致。

## 2. 技术选型

### 2.1 前端
- Vue 3 + Vite
- Vue Router
- Pinia
- Axios
- UI 组件库：`Element Plus`
- Markdown 渲染：`markdown-it`
- Markdown 安全增强：建议引入 HTML 白名单过滤或内容净化方案

前端 UI 方案选择 `Element Plus`，原因如下：
- Vue 3 生态成熟，文档完善，适合快速落地。
- 表单、表格、分页、弹窗、抽屉、上传等后台管理型组件齐全。
- 适合作者侧页面，如登录注册、我的文章、文件夹管理、筛选面板、后续后台审核页。
- 可与自定义样式混合使用，公开首页与文章详情页仍可保持内容型页面风格。

### 2.2 后端
- Java 21
- Spring Boot 3.5.x
- Spring Web
- Validation
- MyBatis-Plus
- MySQL 8.x
- JWT 鉴权
- BCrypt 密码加密

### 2.3 设计原则
- 保持单体架构与模块清晰边界。
- 先实现可上线的内容平台核心闭环，再扩展推荐与治理能力。
- 所有公开展示能力必须建立在“已发布 + 未删除 + 未下架”的统一可见性规则上。

## 3. 系统模块划分

### 3.1 前端页面模块
- 首页：公开文章列表、筛选、排序、兴趣入口。
- 文章详情页：正文阅读、标签、兴趣、点赞、评论、收藏、关注。
- 搜索结果页：文章搜索、作者搜索、标签筛选、兴趣筛选。
- 作者主页：作者资料、已发布文章列表、兴趣标签、关注入口。
- 登录页、注册页。
- 写作页：新建与编辑文章。
- 我的文章页：草稿/已发布管理、搜索、筛选、批量管理入口。
- 文件夹管理页：创建、编辑、删除、查看文件夹内文章。
- 我的收藏页。
- 我的关注页。
- 通知页。
- 个人设置页。
- 管理后台页（Phase 2）：文章审核、评论审核、举报处理。

### 3.2 后端业务模块
- `common`：统一响应、异常处理、工具类。
- `auth`：注册、登录、当前用户、令牌解析。
- `user`：用户资料、作者主页、关注关系。
- `article`：文章、草稿、发布、详情、公开列表、作者列表。
- `folder`：作者自定义文件夹归档。
- `tag`：标签维护、标签查询。
- `interest`：兴趣定义、标签映射、兴趣筛选。
- `comment`：文章评论。
- `like`：点赞关系。
- `favorite`：收藏关系。
- `notification`：互动通知。
- `search`：统一搜索能力。
- `admin`：后台审核与内容治理。

### 3.3 分层设计
- Controller：请求接入、参数校验、权限入口。
- Service：业务规则、事务控制、状态流转。
- Mapper：数据访问。
- Entity：数据实体。
- DTO / VO：接口输入输出对象。

## 4. 页面与路由设计

### 4.1 公共页面
- `/`：首页，展示公开文章列表与兴趣入口。
- `/articles/:id`：文章详情页。
- `/search`：搜索页，支持 `type`、`q`、`tag`、`interest` 等查询条件。
- `/tags/:tagName`：标签文章页。
- `/interests/:interestCode`：兴趣文章页。
- `/u/:username`：作者主页。
- `/login`：登录页。
- `/register`：注册页。

### 4.2 登录后页面
- `/editor/new`：新建文章。
- `/editor/:id`：编辑文章。
- `/me/articles`：我的文章管理。
- `/me/folders`：我的文件夹管理。
- `/me/favorites`：我的收藏。
- `/me/follows`：我的关注。
- `/me/notifications`：我的通知。
- `/me/profile`：个人资料设置。

### 4.3 管理页面（Phase 2）
- `/admin/articles`：文章审核与下架。
- `/admin/comments`：评论审核。
- `/admin/reports`：举报处理。

### 4.4 路由守卫规则
- 首页、文章详情、搜索页、标签页、兴趣页、作者主页允许匿名访问。
- 写作页、我的文章页、文件夹页、收藏页、通知页、设置页需要登录。
- 管理页面需要管理员权限。

### 6.4 表设计原则
- 所有核心业务表保留 `created_at`、`updated_at`，需要逻辑删除的表保留 `deleted_at`。
- 计数字段优先冗余在 `article` 表中，便于列表页快速展示。
- 公开查询的高频字段需要建立索引，如 `status`、`published_at`、`author_id`、`folder_id`、`title`。

## 7. REST API 设计

统一约定：
- Base URL：`/api`
- 返回结构：`{ code, message, data }`
- 成功码：`0`

### 7.1 认证接口
- `POST /api/auth/register`
  - req：`{ username, password, nickname? }`
  - resp：`{ token, user }`
- `POST /api/auth/login`
  - req：`{ username, password }`
  - resp：`{ token, user }`
- `POST /api/auth/logout`
  - req：无
  - resp：成功标记
- `GET /api/auth/me`
  - resp：当前用户信息

### 7.2 文章接口

#### 作者侧
- `POST /api/articles`
  - 创建草稿
- `PUT /api/articles/{id}`
  - 更新文章
- `POST /api/articles/{id}/publish`
  - 发布文章
- `POST /api/articles/{id}/unpublish`
  - 取消发布
- `DELETE /api/articles/{id}`
  - 软删除文章
- `GET /api/articles/mine`
  - 查询我的文章
  - query：`page,size,q,status,tag,folderId,startDate,endDate,sort`

#### 公开侧
- `GET /api/articles`
  - 查询公开文章列表
  - query：`page,size,q,tag,interest,author,sort`
- `GET /api/articles/{id}`
  - 查询文章详情
  - 已发布：公开可访问
  - 草稿：仅作者可访问
- `GET /api/articles/{id}/related`
  - 查询相关文章，基于标签和兴趣

### 7.3 文件夹接口
- `GET /api/folders/mine`
- `POST /api/folders`
- `PUT /api/folders/{id}`
- `DELETE /api/folders/{id}`

### 7.4 标签与兴趣接口
- `GET /api/tags`
- `POST /api/tags`
- `GET /api/interests`
- `GET /api/interests/{code}/articles`

### 7.5 用户与作者主页接口
- `GET /api/users/{username}`
  - 返回作者公开资料
- `GET /api/users/{username}/articles`
  - 返回作者已发布文章列表
- `POST /api/users/{username}/follow`
  - 关注作者
- `DELETE /api/users/{username}/follow`
  - 取消关注
- `GET /api/users/me/follows`
  - 当前用户关注列表

### 7.6 搜索接口
- `GET /api/search`
  - query：`type,q,page,size,tag,interest`
  - `type` 支持 `article`、`user`、`all`

### 7.7 评论接口
- `GET /api/articles/{id}/comments`
- `POST /api/articles/{id}/comments`
- `DELETE /api/comments/{id}`

### 7.8 点赞与收藏接口
- `POST /api/articles/{id}/like`
- `DELETE /api/articles/{id}/like`
- `POST /api/articles/{id}/favorite`
- `DELETE /api/articles/{id}/favorite`

### 7.9 通知接口
- `GET /api/notifications`
- `POST /api/notifications/{id}/read`
- `POST /api/notifications/read-all`

### 7.10 管理后台接口（Phase 2）
- `GET /api/admin/articles`
- `POST /api/admin/articles/{id}/offline`
- `GET /api/admin/comments`
- `DELETE /api/admin/comments/{id}`

## 8. 关键业务规则设计

### 8.1 发布与取消发布
- 新建文章默认为草稿。
- 草稿可反复编辑。
- 只有作者可以发布自己的文章。
- 发布时写入 `publishedAt`。
- 取消发布后文章从公开域移除。

### 8.2 访问控制
- 公开列表只查询 `PUBLISHED` 状态文章。
- 文章详情接口需在服务层判断当前用户与文章状态。
- 作者侧列表接口只返回当前用户自己的文章。
- 管理员接口与普通接口分离。

### 8.3 文件夹归档
- 文件夹仅对作者本人可见。
- 文章在作者侧可按文件夹筛选；公开侧不按文件夹展示。
- 删除文件夹时需将关联文章置为未归档。

### 8.4 标签与兴趣
- 发文时可直接输入标签，系统自动复用已存在标签或新增标签。
- 发布时根据标签映射兴趣，写入文章主兴趣字段。
- 公开端支持按标签与兴趣两类维度筛选。

### 8.5 搜索策略
- MVP 对文章搜索采用标题 + 摘要 + 标签名称的模糊匹配。
- 用户搜索采用用户名 + 昵称的模糊匹配。
- 搜索结果按相关性与时间组合排序，MVP 可先按时间倒序。

### 8.6 互动行为
- 点赞、收藏、关注采用幂等设计。
- 评论默认一级评论，回复能力放到 Phase 2。
- 互动动作成功后生成对应通知。

## 9. 前端交互设计

### 9.1 登录态
- Token 存储在本地。
- Axios 请求拦截器自动附带认证头。
- 接口返回未登录状态时，前端应统一提示并引导登录。

### 9.2 写作页
- 顶部提供保存草稿、发布、预览按钮。
- 支持标签编辑、文件夹选择、摘要填写。
- 发布成功后提示跳转到详情页或继续编辑。

### 9.3 我的文章页
- 默认显示文章列表。
- 顶部提供关键字、日期区间、状态、标签、文件夹筛选条件。
- 每篇文章提供编辑、发布/取消发布、删除操作。

### 9.4 公开端列表与详情
- 列表卡片展示标题、摘要、作者、发布时间、标签、兴趣、互动统计。
- 详情页展示正文、标签、兴趣、相关推荐、评论区、点赞收藏关注入口。

## 10. 错误码建议
- `0`：成功
- `40001`：参数错误
- `40100`：未登录或令牌无效
- `40300`：无权限
- `40400`：资源不存在
- `40900`：状态冲突或重复操作
- `50000`：系统异常

## 11. 与当前工程的对齐建议
- 当前后端已存在 `ArticleController`、`ArticleService` 等命名，应保留 `Article` 术语，不再切换为 `Post`。
- 当前前端路由和接口需从“本人文章 CRUD”演进为“公开文章 + 作者后台”双视角结构。
- 当前工程已有 JWT、统一响应、异常处理基础，可直接扩展认证链路和领域模块。
- 当前数据库初始化脚本仍较简化，后续需补齐文章、标签、文件夹、评论、点赞、收藏、关注、通知等表。

## 12. 双视角设计补充

### 12.1 设计原则补充

系统设计必须同时覆盖两套页面语义：

- **作者域**：`/editor/new`、`/editor/:id`、`/me/articles`、`/me/folders`
- **公开域**：`/`、`/articles/:id`、`/search`、`/tags/:tagName`、`/interests/:interestCode`

这意味着：

- 作者域接口与公开域接口不能混用同一访问规则。
- “我的文章”查询必须允许返回草稿。
- “公开文章”查询必须默认附加 `PUBLISHED` 条件。

### 12.2 页面设计补充矩阵

| 页面 | 角色 | 核心目标 | 关键能力 |
| --- | --- | --- | --- |
| 首页 `/` | 访客 / 注册用户 | 发现内容 | 浏览公开文章、搜索文章、搜索作者、按标签与兴趣筛选 |
| 文章详情 `/articles/:id` | 所有人 / 作者本人 | 阅读与互动 | 阅读正文、查看标签兴趣、点赞、留言、作者编辑入口 |
| 写作页 `/editor/new` | 作者 | 新建文章 | 录入标题、摘要、正文、标签、文件夹；保存草稿；发布 |
| 编辑页 `/editor/:id` | 作者 | 维护文章 | 更新内容、重新发布、取消发布 |
| 我的文章 `/me/articles` | 作者 | 内容管理 | 按关键字、日期、状态、文件夹筛选；编辑；发布管理 |
| 文件夹管理 `/me/folders` | 作者 | 归档管理 | 创建、编辑、删除文件夹 |

### 12.3 接口设计补充

- `GET /api/articles/mine`：返回作者自己的全部文章，支持 `keyword/status/startDate/endDate/folderId`。
- `GET /api/articles`：只返回公开文章，支持 `q/tag/interest/author`。
- `GET /api/articles/{id}`：若为已发布文章则公开可访问；若为草稿，只允许作者访问。
- `POST /api/articles/{id}/publish`：发布时执行标签到兴趣映射。
- `POST /api/articles/{id}/comments`：仅登录用户可对已发布文章留言。
- `POST /api/articles/{id}/like`：仅登录用户可对已发布文章点赞，且要求幂等。
