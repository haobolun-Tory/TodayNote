# TodayNote 博客系统开发实施计划

## 1. 文档目标

本文档基于以下文档形成面向研发执行的落地计划：

- [docs/01-需求文档.md](docs/01-%E9%9C%80%E6%B1%82%E6%96%87%E6%A1%A3.md)
- [docs/02-设计文档.md](docs/02-%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3.md)
- [docs/03-架构方案.md](docs/03-%E6%9E%B6%E6%9E%84%E6%96%B9%E6%A1%88.md)

本文档不再讨论“做什么”，而是明确“先做什么、后做什么、每个模块拆成哪些故事、每个故事控制在多久内完成”。

目标：

- 给开发提供清晰的模块优先级。
- 将功能拆分为可独立交付的用户故事。
- 每个故事尽量控制在 $0.5 \sim 2$ 天内完成。
- 每个故事都是一个完整功能闭环，具备明确验收点。

---

## 2. 规划原则

### 2.1 研发优先级原则

按以下顺序推进：

1. **先打基础**：项目基线、鉴权、全局状态、基础 UI 框架。
2. **先作者闭环**：写文章、草稿、发布、我的文章、文件夹。
3. **再公开闭环**：公开列表、详情、搜索、标签、兴趣。
4. **再互动闭环**：点赞、留言、收藏、关注、通知。
5. **最后增强能力**：作者主页增强、后台审核、推荐与搜索升级。

### 2.2 故事拆分原则

- 一个故事必须对应一个用户可感知的功能结果。
- 一个故事尽量不跨越太多模块边界。
- 一个故事应当可以独立测试和验收。
- 单个故事工期最好不超过 2 天。
- 若某项功能超过 2 天，应继续拆细。

### 2.3 交付节奏建议

建议按照“小步快跑”方式推进：

- 每 3~5 个故事形成一个小迭代。
- 每个小迭代结束后做一次联调与演示。
- 先保证主链路可跑通，再补体验与扩展能力。

## 5. 模块拆分与故事清单

以下故事按“建议开始顺序”排列。

## 模块 A1：基础工程与 UI 基线

### A1-01：统一前端 UI 基础框架
- **目标**：完成 `Element Plus` 的全局接入和页面基础布局统一。
- **范围**：按钮、表单、表格、弹窗、消息提示、基础栅格。
- **前置依赖**：无。
- **预计工期**：0.5 天。
- **验收标准**：新页面可以直接使用统一 UI 组件；有统一按钮、输入框、消息提示风格。

### A1-02：统一前端路由结构与页面骨架
- **目标**：搭建公开域与作者域的基础路由骨架。
- **范围**：`/`、`/login`、`/register`、`/editor/new`、`/me/articles`、`/me/folders`。
- **前置依赖**：A1-01。
- **预计工期**：0.5 天。
- **验收标准**：路由可访问，页面壳结构清晰，导航可跳转。

### A1-03：统一响应与错误提示机制
- **目标**：前后端形成统一返回码与统一提示机制。
- **范围**：成功提示、错误提示、未登录跳转、接口异常提示。
- **前置依赖**：A1-01。
- **预计工期**：0.5 天。
- **验收标准**：常见错误都有统一提示，不同页面不重复写错误处理逻辑。

---

## 模块 A2：账号与认证模块

### A2-01：用户注册
- **目标**：支持用户名 + 密码注册。
- **范围**：注册页、注册接口、参数校验、用户名唯一性校验。
- **前置依赖**：A1-02、A1-03。
- **预计工期**：1 天。
- **验收标准**：用户可以注册成功；重复用户名提示明确。

### A2-02：用户登录
- **目标**：支持用户名 + 密码登录。
- **范围**：登录页、登录接口、JWT 返回。
- **前置依赖**：A2-01。
- **预计工期**：1 天。
- **验收标准**：登录成功后可进入系统并拿到 Token。

### A2-03：登录态持久化与当前用户信息
- **目标**：刷新页面后仍可保持登录态。
- **范围**：Token 存储、`/api/auth/me`、前端用户状态仓库。
- **前置依赖**：A2-02。
- **预计工期**：1 天。
- **验收标准**：刷新后登录态不丢失；页面可拿到当前用户信息。

### A2-04：受保护页面路由守卫
- **目标**：未登录不能访问作者域页面。
- **范围**：路由守卫、统一跳转登录页。
- **前置依赖**：A2-03。
- **预计工期**：0.5 天。
- **验收标准**：未登录访问作者域页面时自动跳转登录。

## 模块 B1：文章写作与草稿

### B1-01：新建文章草稿
- **目标**：作者可创建文章并保存为草稿。
- **范围**：写作页、创建草稿接口、标题与正文校验。
- **前置依赖**：A2-04。
- **预计工期**：1 天。
- **验收标准**：保存后文章状态为 `DRAFT`，仅作者自己可见。

### B1-02：编辑已有草稿
- **目标**：作者可进入编辑页修改已有文章。
- **范围**：编辑接口、详情回填、保存更新。
- **前置依赖**：B1-01。
- **预计工期**：1 天。
- **验收标准**：已保存文章可再次进入编辑并更新成功。

### B1-03：写作页支持摘要与标签输入
- **目标**：文章支持填写摘要和多个标签。
- **范围**：写作表单字段、后端存储结构。
- **前置依赖**：B1-02。
- **预计工期**：1 天。
- **验收标准**：可输入摘要和标签，保存后可正确显示。

### B1-04：写作页支持 Markdown 预览
- **目标**：作者发布前可预览 Markdown 效果。
- **范围**：预览区域或预览弹窗。
- **前置依赖**：B1-02。
- **预计工期**：0.5~1 天。
- **验收标准**：作者可在写作页查看渲染效果。

### B2-01：我的文章列表基础版
- **目标**：作者能看到自己的全部文章。
- **范围**：列表接口、列表页、状态展示。
- **前置依赖**：B1-01。
- **预计工期**：1 天。
- **验收标准**：列表只返回当前用户文章，状态清晰可见。

### B2-02：按关键字搜索我的文章
- **目标**：支持标题 / 摘要关键字搜索。
- **范围**：搜索输入框、列表筛选接口。
- **前置依赖**：B2-01。
- **预计工期**：0.5~1 天。
- **验收标准**：输入关键字后能筛出匹配文章。

### B2-03：按日期范围筛选我的文章
- **目标**：支持按日期区间筛选文章。
- **范围**：日期选择器、接口查询条件。
- **前置依赖**：B2-01。
- **预计工期**：0.5~1 天。
- **验收标准**：可按起止日期找到历史文章。

### B2-04：按状态筛选我的文章
- **目标**：支持草稿 / 已发布筛选。
- **范围**：状态筛选组件、后端查询条件。
- **前置依赖**：B2-01。
- **预计工期**：0.5 天。
- **验收标准**：切换状态时列表结果准确。

### B2-05：删除自己的文章
- **目标**：作者可删除自己的文章。
- **范围**：删除按钮、确认弹窗、删除接口。
- **前置依赖**：B2-01。
- **预计工期**：0.5 天。
- **验收标准**：删除后文章不再出现在作者列表和公开域。

## 模块 B3：文件夹归档

### B3-01：创建文件夹
- **目标**：作者可创建自己的文件夹。
- **范围**：文件夹管理页、创建接口。
- **前置依赖**：A2-04。
- **预计工期**：0.5 天。
- **验收标准**：创建后文件夹可立即出现在列表中。

### B3-02：编辑文件夹
- **目标**：作者可修改文件夹名称与描述。
- **范围**：编辑接口、编辑表单。
- **前置依赖**：B3-01。
- **预计工期**：0.5 天。
- **验收标准**：修改后列表展示最新内容。

### B3-03：删除文件夹并回收文章到未归档
- **目标**：删除文件夹时，原归档文章回到未归档状态。
- **范围**：删除接口、关联文章处理。
- **前置依赖**：B3-01。
- **预计工期**：1 天。
- **验收标准**：删除文件夹后文章仍存在，只是取消归档。

### B3-04：写作页选择文件夹归档
- **目标**：文章可关联到某个文件夹。
- **范围**：写作页文件夹下拉框、保存逻辑。
- **前置依赖**：B3-01、B1-02。
- **预计工期**：0.5 天。
- **验收标准**：保存后文章与文件夹关联成功。

### B3-05：我的文章按文件夹筛选
- **目标**：作者能按文件夹查看文章。
- **范围**：文件夹筛选条件、查询接口。
- **前置依赖**：B3-04、B2-01。
- **预计工期**：0.5 天。
- **验收标准**：选择文件夹后只展示该文件夹下文章。

### B4-01：发布文章
- **目标**：草稿可发布为公开文章。

- **前置依赖**：B1-02。
- **预计工期**：1 天。

### B4-02：取消发布
- **目标**：已发布文章可回到草稿状态。
- **范围**：取消发布按钮、接口、公开域剔除逻辑。
- **前置依赖**：B4-01。
- **预计工期**：0.5~1 天。
- **验收标准**：取消发布后公开列表不可见，作者仍可编辑。

### B4-03：草稿访问控制
- **目标**：非作者无法访问草稿详情。
- **范围**：详情接口权限校验。
- **前置依赖**：B4-01。
- **预计工期**：0.5 天。
- **验收标准**：非作者访问草稿返回无权限。

## 模块 D2：收藏与关注

### D2-01：收藏文章
- **目标**：登录用户可收藏文章。
- **范围**：收藏接口、详情页收藏按钮。
- **前置依赖**：C2-01、A2-03。
- **预计工期**：1 天。
- **验收标准**：文章可被收藏，重复点击不重复收藏。

### D2-02：取消收藏
- **目标**：已收藏文章可取消收藏。
- **范围**：取消收藏接口、前端状态切换。
- **前置依赖**：D2-01。
- **预计工期**：0.5 天。
- **验收标准**：取消后收藏状态和统计恢复正确。

### D2-03：关注作者
- **目标**：登录用户可关注作者。
- **范围**：关注接口、作者主页关注按钮。
- **前置依赖**：C4-01、A2-03。
- **预计工期**：1 天。
- **验收标准**：可关注作者，状态正确保存。

### D2-04：取消关注作者
- **目标**：已关注作者可取消关注。
- **范围**：取消关注接口、状态切换。
- **前置依赖**：D2-03。
- **预计工期**：0.5 天。
- **验收标准**：取消关注成功，关注状态正确刷新。

## 模块 D3：通知与基础统计

### D3-01：文章统计字段更新
- **目标**：阅读、点赞、评论、收藏等统计字段能正确累计。
- **范围**：统计字段写回逻辑。
- **前置依赖**：D1、D2 相关故事。
- **预计工期**：1 天。
- **验收标准**：列表和详情中的统计数字一致。

### D3-02：互动通知写入
- **目标**：评论、点赞、收藏、关注后为作者生成通知。
- **范围**：通知表、通知写入逻辑。
- **前置依赖**：D1-01、D1-03、D2-01、D2-03。
- **预计工期**：1.5 天。
- **验收标准**：完成互动后，目标作者有对应通知记录。

### D3-03：通知列表页基础版
- **目标**：用户可查看自己的通知列表。
- **范围**：通知查询接口、通知页基础展示。
- **前置依赖**：D3-02。
- **预计工期**：1 天。
- **验收标准**：用户进入通知页可看到自己的互动通知。

### D3-04：通知已读
- **目标**：支持单条已读和全部已读。
- **范围**：已读接口、前端操作按钮。
- **前置依赖**：D3-03。
- **预计工期**：0.5~1 天。
- **验收标准**：已读状态可更新且列表刷新正确。

- **前置依赖**：D1-03。
- **预计工期**：1 天。
- **验收标准**：管理员可删除评论，公开详情中不再显示。

## 7. 研发协作建议

### 7.1 前后端并行切分建议

可按以下方式并行：

- **后端优先**：接口、权限、数据模型、状态流转。
- **前端并行**：页面骨架、组件拆分、假数据联调。
- **联调顺序**：认证 → 作者文章 → 文件夹 → 公开列表 → 详情 → 搜索 → 互动。

### 7.2 测试建议

每个故事完成后至少执行：

- 接口级自测
- 页面级手工自测
- 正常流程测试
- 异常流程测试
- 权限边界测试

### 7.3 故事完成定义（Definition of Done）

一个故事完成，至少要满足：

1. 代码提交完成。
2. 前后端联调通过。
3. 验收标准全部满足。
4. 关键异常路径已验证。
5. 不破坏已有主流程。

## 10. 总结

本计划建议按“基础 → 作者 → 公开 → 互动 → 增强”的顺序推进。

最重要的原则只有两个：

- **先让主链路跑通**。
- **每次只做一个可完整验收的故事**。

如果严格执行本计划，研发可以持续交付、持续联调、持续演示，而不是一次性堆大功能。
