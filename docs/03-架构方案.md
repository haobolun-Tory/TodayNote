# TodayNote 博客系统架构方案

## 1. 架构目标
架构方案需要同时支撑两类核心业务链路：
- 作者侧的写作、草稿、发布、文件夹归档、内容管理、数据查看。
- 公开侧的浏览、搜索、标签筛选、兴趣筛选、点赞、评论、收藏、关注与通知。

在 MVP 阶段，系统应保持前后端分离、单体后端、模块清晰、易于快速交付；同时在数据模型与模块设计上预留互动、审核、推荐、全文检索的扩展空间。

## 2. 总体架构

### 2.1 架构风格
采用前后端分离 + 单体后端架构：
- 前端：Vue 3 SPA，负责公开浏览与作者后台交互。
- 后端：Spring Boot 单体服务，统一提供认证、内容、互动与管理接口。
- 数据库：MySQL，承担业务主存储。

### 2.2 MVP 约束
- 不拆微服务。
- 不引入消息队列作为强依赖。
- 不引入 Redis 作为上线前置条件。
- 不引入 Elasticsearch 作为 MVP 必需项。

### 2.3 演进方向
- 可扩展到缓存层、搜索层、对象存储、消息通知与推荐服务。
- 通过清晰模块边界降低未来拆分成本。

## 3. 逻辑架构视图

### 3.1 用户接入层
- 公开 Web UI：文章列表、详情、搜索、标签页、兴趣页、作者主页。
- 作者工作台：写作页、我的文章、文件夹管理、收藏、关注、通知、个人设置。
- 管理后台：内容审核、评论管理、举报处理。

### 3.2 应用服务层
- 认证服务：注册、登录、当前用户。
- 文章服务：创建、编辑、发布、取消发布、详情、公开列表、作者列表。
- 文件夹服务：归档管理。
- 标签与兴趣服务：标签查询、兴趣映射、兴趣筛选。
- 搜索服务：文章与用户统一搜索。
- 互动服务：点赞、评论、收藏、关注。
- 通知服务：互动通知与已读状态。
- 管理服务：下架、删除、审核与治理。

### 3.3 数据层
- MySQL 负责用户、文章、标签、兴趣映射、互动、通知等主数据存储。
- 后续如引入 Redis，可用于热点文章、标签统计、通知未读数缓存。
- 后续如引入 Elasticsearch，可用于统一搜索升级。

## 4. 分层架构设计

### 4.1 后端分层
- **Controller 层**：接收 HTTP 请求，做参数校验、身份校验入口与统一响应封装。
- **Service 层**：承载业务规则，包括发布状态流转、公开可见性、归档规则、兴趣映射、幂等互动等。
- **Mapper 层**：负责数据库访问。
- **Domain / Entity 层**：定义文章、用户、文件夹、标签、兴趣、评论、点赞、收藏、关注、通知等实体。

### 4.2 前端分层
- 页面层：负责页面结构与场景编排。
- 组件层：负责通用 UI 组件，如文章卡片、搜索栏、评论区、标签组件。
- Store 层：负责用户登录态、通知计数、筛选状态等跨页面状态。
- API 层：统一接口封装与错误处理。

## 5. 关键技术决策

### 5.1 认证与会话
- 方案采用 JWT。
- 登录成功后由后端签发令牌。
- 前端在请求中附带 `Authorization: Bearer <token>`。
- 后端通过过滤器或拦截器解析令牌，构建当前用户上下文。

选择 JWT 的原因：
- 适合前后端分离。
- 接入简单。
- 便于后续扩展到多端。

### 5.2 内容存储与渲染
- 数据库存储 Markdown 原文 `content_md`。
- MVP 采用前端渲染，后端返回 Markdown 内容。
- 前端渲染时必须结合 HTML 白名单或内容净化，避免 XSS 风险。

### 5.3 公开可见性控制
- 是否公开由文章状态、删除状态、下架状态共同决定。
- 公开列表、标签页、兴趣页、搜索结果页统一复用同一套可见性规则。
- 草稿永远不应出现在公开域。

### 5.4 搜索策略
- MVP 使用 MySQL 模糊查询实现文章与用户搜索。
- 文章搜索范围：标题、摘要、标签。
- 用户搜索范围：用户名、昵称。
- 后续扩展 Elasticsearch，不改变上层接口语义。

### 5.5 兴趣映射策略
- 兴趣不是作者直接维护的主数据，而是平台侧定义的主题体系。
- 发文时作者打标签。
- 发布时系统根据标签到兴趣的映射关系计算文章主兴趣。
- 该策略保证实现简单、规则透明、可维护。

### 5.6 互动与通知策略
- 点赞、收藏、关注采用幂等接口设计。
- 评论采用一级评论模型，后续可扩展楼中楼。
- 互动行为成功后写入通知记录；MVP 可同步写库，后续再异步化。

## 6. 模块架构与依赖关系

### 6.1 核心模块关系
- `auth` 依赖 `user`。
- `article` 依赖 `user`、`folder`、`tag`、`interest`。
- `search` 依赖 `article` 与 `user`。
- `comment`、`like`、`favorite` 依赖 `article` 与 `user`。
- `notification` 依赖互动模块的事件结果。
- `admin` 依赖 `article`、`comment`、`user`。

### 6.2 解耦原则
- 文章模块是核心领域。
- 文件夹归档只在作者域生效，不参与公开域主逻辑。
- 兴趣依赖标签映射生成，不与文件夹、分类混用。
- 统计数字优先由文章聚合字段承载，复杂统计后续再拆分析模块。

## 7. 数据架构要点

### 7.1 主体数据
- 用户：身份与资料。
- 文章：核心内容。
- 文件夹：作者私有归档。
- 标签：开放主题关键词。
- 兴趣：平台公共主题维度。

### 7.2 关系数据
- 文章与标签：多对多。
- 标签与兴趣：多对一或加权映射。
- 用户与文章互动：点赞、收藏、评论。
- 用户与用户关系：关注。

### 7.3 冗余数据
- `view_count`、`like_count`、`comment_count`、`favorite_count` 建议冗余在文章表。
- 用户主页的部分统计可按需聚合，不必全部冗余。

## 8. 安全架构

### 8.1 认证安全
- 密码使用 BCrypt。
- JWT 设置过期时间。
- 后续可增加刷新令牌。

### 8.2 授权安全
- 写操作必须校验当前用户身份。
- 编辑、发布、删除文章必须校验 `authorId == currentUserId`。
- 管理接口必须校验管理员角色。

### 8.3 内容安全
- Markdown 渲染必须做 XSS 防护。
- 评论内容应过滤危险脚本输入。
- 后台下架机制应覆盖违规文章和违规评论。

### 8.4 数据安全
- 敏感配置通过环境变量管理。
- 数据删除优先采用逻辑删除，保留审计能力。

## 9. 部署方案

### 9.1 本地开发
- MySQL：本地服务或 Docker。
- 后端：Maven 启动。
- 前端：Vite 开发服务启动。

### 9.2 部署形态
- 前端构建为静态资源，由 Nginx 托管。
- 后端以 Spring Boot 应用运行。
- 数据库独立部署。

### 9.3 配置策略
- 数据源配置放在环境区分配置文件中。
- JWT 密钥、上传路径等敏感配置通过环境变量注入。

## 10. 可扩展设计

### 10.1 缓存
- 热门文章列表。
- 兴趣页热点内容。
- 用户未读通知数。

### 10.2 搜索升级
- 将文章搜索从模糊匹配升级为全文检索。
- 增强标签、兴趣、作者的联合检索能力。

### 10.3 对象存储
- 支持封面与正文图片上传。
- 统一静态资源访问策略。

### 10.4 推荐与运营
- 基于兴趣、标签、关注关系生成推荐流。
- 为管理后台提供内容质量与活跃度指标。

## 11. 风险与约束
- Markdown XSS 是首要安全风险，必须优先落实净化策略。
- 当前工程尚未完整实现登录态上下文注入，后续需补齐统一鉴权链路。
- 搜索、统计、互动计数在数据量上升后需做索引与缓存优化。
- 文件夹、标签、兴趣三套体系职责必须严格区分，避免模型混乱。
- 文档与代码当前存在“仅本人文章 CRUD”与“公开博客平台”之间的差距，实施时需按模块逐步演进。

## 12. 文档一致性说明
- 本文统一使用“文章 Article”术语。
- 文件夹是作者私有归档结构，不等同于分类，也不等同于兴趣。
- 兴趣来源于标签映射，用于公开检索与发现。
- 留言统一归入文章评论能力。
- 收藏、关注、通知、审核已纳入整体架构，但允许分阶段交付。

## 13. 双链路架构补充

### 13.1 作者生产链路

认证 → 写作页 → 草稿存储 → 文件夹归档 → 我的文章检索 → 发布 → 继续维护。

该链路的架构重点：

- 允许访问草稿。
- 支持日期与关键字检索。
- 支持文件夹归档。
- 发布动作触发兴趣映射。

### 13.2 公开消费链路

公开列表 → 搜索 / 标签 / 兴趣筛选 → 文章详情 → 点赞 / 留言 → 持续发现。

该链路的架构重点：

- 只允许访问已发布文章。
- 搜索和筛选都依赖统一公开可见性规则。
- 点赞与评论必须依赖登录态。

### 13.3 架构实施优先级

1. **第一优先级**：作者写作、草稿、发布、我的文章管理、文件夹归档、公开列表与详情。
2. **第二优先级**：标签与兴趣筛选、文章搜索、作者搜索、点赞、留言。
3. **第三优先级**：收藏、关注、通知、后台审核、推荐与搜索升级。
